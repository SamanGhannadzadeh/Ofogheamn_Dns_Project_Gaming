# مش افق امن — اتصال نودها به هم برای کمترین پینگ

## ایده

هر نود به‌تنهایی خوب است؛ ولی گاهی مسیر مستقیم یک نود تا سرور بازی بد است و مسیرش از دل یک نود دیگر بهتر. مش همین را خودکار می‌کند:

هر نودی که مش را روشن کرده، هر دقیقه سه چیز را اندازه می‌گیرد:

1. پینگ خودش تا چند سرور بازی (هدف‌های ثابت)
2. پینگ خودش تا هر نود همتای مش
3. پینگ همتاها تا سرورهای بازی (از گزارش خودشان می‌خواند)

بعد برای هر مسیر جمع می‌زند:

```
مسیر مستقیم:        پینگ(من ← بازی)
مسیر از همتا:       پینگ(من ← همتا) + پینگ(همتا ← بازی)
```

هر کدام کمتر بود، خروجی همان می‌شود: لیست‌های بازی از DNS همان همتا زنجیره می‌شوند و اگر خروجی تونل روشن باشد، ترافیک کلاینت‌های WireGuard هم از همان همتا رد می‌شود. برای جلوگیری از نوسان، مسیر فقط وقتی عوض می‌شود که مسیر تازه دست‌کم ۵ میلی‌ثانیه بهتر باشد.

## قانون اصلی: فقط با رضایت دوطرفه

نود فقط به نودی وصل می‌شود که **او هم مش را روشن کرده و از همین نرم‌افزار استفاده می‌کند**. مش در نصب پیش‌فرض خاموش است؛ روشن‌کردنش دست صاحب نود است.

## راه‌اندازی (هر دو نود)

```bash
# روی هر نود: یک کلید مشترک با همتا توافق کنید
ofogheamn-dns mesh init                 # کلید تصادفی می‌سازد و نشان می‌دهد
ofogheamn-dns mesh key <کلید مشترک>      # یا کلید توافقی را بگذارید

# همتا را معرفی کنید (نام، آدرس و پورت WireGuard مش، کلید عمومی مش، IP مش)
ofogheamn-dns mesh add-peer frankfurt2 203.0.113.7:51822 <PUBKEY> 10.99.0.2

ofogheamn-dns mesh on
ofogheamn-dns mesh status               # نمرهٔ هر مسیر و خروجی فعلی
```

کلید عمومی مش هر نود بعد از اولین اجرا در وضعیت تونل مش دیده می‌شود (`wg show wg-mesh`) و فایل کانفیگش `/etc/ofogheamn-dns/wg-mesh.conf` است؛ پورت گزارش مش 51821 و پورت تونل مش 51822 است — روی فایروال فقط برای IP همتاها بازشان کنید.

## نکته‌های صادقانه

- مش جادو نمی‌کند: اگر مسیر مستقیم بهترین باشد، همان می‌ماند (نمره‌ها را در `mesh status` می‌بینی).
- زیرشبکهٔ کلاینت‌ها (10.66.0.0/24) بین نودها مشترک است؛ برای خروجی تونلِ بین‌نودی، همتاها باید برگشت ترافیک را هماهنگ کنند — زنجیرهٔ DNS بدون این هماهنگی هم کار می‌کند.
- گزارش هر نود با کلید مشترک محافظت می‌شود؛ کلید را فقط به همتاهای خودت بده.
